# `@agentic-ddd` v0 — Índice dos planos

**Spec:** [`docs/superpowers/specs/2026-10-06-agentic-ddd-v0-design.md`](../specs/2026-10-06-agentic-ddd-v0-design.md)

O v0 tem quatro subsistemas que dependem uns dos outros. Cada plano entrega software funcionando e testado por si só, e o plano seguinte é escrito **depois** que o anterior estiver implementado, sobre as interfaces reais do código (evita que um plano escrito de antemão divirja do que foi construído).

| # | Plano | Entrega | Critérios de aceite da spec (§15) | Status |
|---|---|---|---|---|
| 1 | [Fundação e compilador de documentação](2026-10-06-v0-01-fundacao-compilador.md) | toolchain Bun, `core`, decorators + registry, IR, validação, renderers (skills de runtime e dev, bloco do `AGENTS.md`), `compile` / `--check` / `--report`, exemplo `orders` implementado, teste de arquitetura, CI, README | 1 (parcial: sem lock), 5, 6, 7, 8 | escrito |
| 2 | Lock, changes e `verify` | comando `ir`; teste de equivalência Zod ↔ JSON Schema (§12.1, exige decidir o validador de JSON Schema); `domain.lock.json`, diff semântico com classificação, propostas, reconciliação, `--draft-change`, `history.md`, JUnit + `covers`, `verify <change>` (G1–G6), change `0001` e `0002` do exemplo | 1 (completo), 4 | a escrever após o plano 1 |
| 3 | Estado do projeto e coordenação | detecção de `notImplemented()`, grafo de work items, `status`, `next` (ondas), `packet`, `verify --item`, gate G7, fixture "declaração primeiro" | 9 | a escrever após o plano 2 |
| 4 | Runtime e integração Nest | `LlmPort`, `FakeLlm`, loop do operator, `ApprovalPort`, `EventBus`, `OperatorRunResult`, `AgenticModule`, `orders.module.ts`, e2e de runtime e de aprovação | 2, 3 | a escrever após o plano 3 |

O plano 4 depende só do plano 1 (skill de runtime + `ir-hash`); pode ser antecipado para depois do plano 1 se for preferível ver o operator rodando antes do fluxo de changes.
