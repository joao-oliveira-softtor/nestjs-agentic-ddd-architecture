# Plano 6 — Runner de avaliações Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. A execução deste plano não foi solicitada nesta sessão; não iniciar o runner ao versionar os documentos.

**Goal:** Avaliar compreensão das skills e implementação dos cinco itens tasks com agentes reais, julgamento determinístico e evidências independentes.

**Architecture:** Tooling Bun em `scripts/evals`, com contratos/juiz, supervisor/isolation, dois percursos de avaliação e adapters scripted/Codex/Cursor. O runner atua como gerente determinístico, congela os hashes e aceita somente submissões verificadas em cópias independentes. JSON é a fonte do Markdown e dos cálculos.

**Tech Stack:** Bun 1.4.2, TypeScript, Zod, APIs node:*, TypeScript AST e bubblewrap; sem SDK de LLM e sem novo port público.

**Spec:** [2026-10-08-v0-06-agent-evals-design.md](../specs/2026-10-08-v0-06-agent-evals-design.md).

## Global Constraints

- Execução real inicial em **Linux/WSL com bubblewrap**, sem fallback para processo desprotegido.
- Framework e runtime mantêm suas interfaces; `src/core` preserva sua fronteira; compiler/runtime não passam a se importar.
- Não evoluir `examples/orders`, gerar soluções no tutorial, implementar Planos 7–8, treinar modelos, usar LLM-juiz ou criar ranking público amplo.
- Exigir um único JSON, sem cercas ou prosa. Strings de resposta não são normalizadas.
- Limite de **8 MiB por tentativa** nos streams somados; **2 segundos** de tolerância para cancelamento, depois encerrar descendentes.
- Deadline de cada comando confiável de consulta/verificação: **120 segundos**, também subordinado ao orçamento total.
- Referência: 30 sessões, pergunta 120000 ms, implementação 600000 ms, total 5400000 ms, uma correção por item, repetitions/concurrency 1.
- Sem `--real`, apenas adapters scripted podem executar. Nenhuma execução paga é autorizada durante a implementação offline.
- Modelo/uso/custo sem evidência é indisponível. Não estabelecer threshold de modelo antes da baseline.

## Review Focus

1. Links, ancestrais simbólicos ou dependências retornam à origem: resolver destinos antes de copiar/montar e testar escrita/leitura proibida (etapa 2).
2. Agente declara done com teste fraco, altera outro corpo ou desloca source sem mudar hash: auditar antes de executar e exigir oráculos privados (etapa 4).
3. Proposta arquivada perde critérios no packet: handoff complementa critérios e a cobertura é do executor, não do oráculo (etapa 4).
4. Timeout deixa filhos escrevendo ou streams bloqueiam coleta: supervisor encerra árvore, drena simultaneamente e preserva motivo (etapa 2).
5. Eventos nativos sem mensagem final/modelo/usage ou métricas degeneradas: distinguir transporte, protocolo e indisponibilidade, sem inventar metadados (etapas 5–6).

Interfaces centrais da spec (`AdapterRequest`, `AdapterResult`, `EvalAdapter`, `Answer`, `ImplementationReply`, `Measured`, `Usage`) vivem em contracts. Definir ali também:

- `RunManifest`: campos da spec §2; `EvalConfiguration` é um elemento de configurations.
- `EvalVerdict`: `correct|incorrect|malformed|timeout|infra_error|not_run`.
- `CaseResult`: grupo Caso de skill da spec §6; `ItemResult`: grupo Benchmark, com tentativas e accepted.
- `EvalReport`: grupos da spec §6, `schemaVersion: 1`; `RunOptions = { outDir: string; real: boolean; signal: AbortSignal }`.
- `ProcessRequest = { argv: readonly string[]; cwd: string; env: Readonly<Record<string, string>>; timeoutMs: number; evidenceDir: string }`; `ProcessResult` tem status de transporte, exitCode/signal, stdout/stderr saneados, duração e paths de evidência.
- `PreparedSource`: commit, fingerprints de origem, snapshot do framework e dependências somente leitura; `AttemptWorkspace`: root/configPath/baseline e identificação dos mounts; `AuditReport`: ok e findings; `VerificationEvidence`: comandos/códigos/streams, gate reports, JUnit, oráculos e integridade.

Tipos de evidência referenciam os tipos públicos atuais do compilador quando úteis, sem alterá-los. Não criar imports do compiler para o runner nem do runner para os building blocks.
