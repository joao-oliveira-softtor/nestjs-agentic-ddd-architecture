# ADR-0007 — MCP as the domain entry point (inverted spec-driven development)

- **Status:** Proposed (decided with the user in a grilling session on 2026-10-27; accepted on merge)
- **Date:** 2026-10-27
- **Supersedes:** [ADR-0005](ADR-0005.md) D7 and D8 where they conflict (read-only remote MCP, no repository access, no write tools).
- **Related:**
  - [ADR-0003](ADR-0003.md) (deterministic briefs, `ROLE_CORES`, cycle-21 baseline);
  - [ADR-0005](ADR-0005.md) D8 (the `@Controller` gate principle for #11);
  - issues #69 (remote MCP) and #11 (HTTP channel for operators), both absorbed by this decision.

In this ADR, `D1`–`D14` are the decisions of this document. It is the first ADR written in English (D13); ADR-0001 to ADR-0006 stay in Portuguese as history.

## Context

The compiler turns decorated TypeScript into a deterministic contract: IR, lock, packets, skills and briefs. Today that contract is only consumed inside this repository: by developers' coding agents through the local stdio MCP (#68, read-only) and by the runtime that executes operators in-process.

The goal is wider. Three kinds of users should reach the domain through one door:

| User | Reads the domain | Reads the authoring skill | Proposes a change | Runs an operator | Writes code |
|---|---|---|---|---|---|
| Non-technical client (Claude web, ChatGPT) | ✓ | ✓ | ✓ (POC for a specific pain) | ✓ (internal use) | — |
| Developer (Claude Code, Codex) | ✓ | ✓ | ✓ | — | ✓ (supervised, locally) |
| External system | ✓ | ✓ | ✓ | ✓ | — |
| Unattended implementer on the server | — | — | reads proposals | — | ✓ (gated) |

This is **inverted spec-driven development**: the specification starts as decorators in code and is compiled deterministically. A client's AI never writes decorators. It describes a change; the framework renders and compiles it, and returns the compiled specification, which any agent, in any language, can implement.

## Decisions

| ID | Decision | Rejected alternatives |
|---|---|---|
| D1 | **MCP is the single entry point of the domain**, with access per capability. Delivery is phased (see Consequences); the table above is the target. | A REST API per capability: every client (Claude web, ChatGPT, coding CLIs) already speaks MCP. |
| D2 | **Two MCP servers, one auth layer.** The **domain MCP** runs outside the application, against the repository or a published lock: domain queries, authoring skill, proposals. The **runtime MCP** runs inside the Nest application, because operators need its DI and storage. Both share the same resource-server and scope code. | One server inside the app: production has no repository and must not write to it, and querying the domain would depend on the app being up. |
| D3 | **Authentication follows the MCP authorization spec.** The framework implements the **OAuth 2.1 resource server**: Protected Resource Metadata (RFC 9728), bearer validation, audience check. The **authorization server is external**, configured by issuer (Auth0, Keycloak, Entra, Cognito…). Without a valid token no tool answers. Listening defaults to `127.0.0.1`. | A framework-owned authorization server (login, consent, client registration): a separate product and a large security surface. App-supplied Nest guards only: not what MCP clients negotiate. |
| D4 | **Scopes per capability**: `domain:read`, `skill:read`, `change:propose`, `change:publish`, `operator:run:<name>`, each with an optional module suffix (`change:propose:orders`). No suffix means every module. | Scopes per server only: cannot let a client read but not propose. |
| D5 | **Operators are MCP tools on the runtime MCP**, served by **one generic controller** in `@agentic-ddd/nestjs` that hosts the Streamable HTTP endpoint. The `test/architecture.test.ts` gate changes from "no `@Controller`" to "only that file, by name"; `examples/**` and domain code stay controller-free. Exposure is opt-in through a separate `AgenticHttpModule`; `AgenticModule` does not change. The application **allowlists** which of its operators are exposed; an unlisted operator is absent from `tools/list`. | REST `POST /operators/:name/runs` (the original #11): a second protocol with its own auth. Registering routes through `HttpAdapterHost` to keep the gate literally green: loses Nest guards and pipes. A bare handler each app wires itself: boilerplate and forgotten auth. |
| D6 | **Operator `context` comes only from the server**, derived from token claims by an application resolver (`(claims) => ({ userId: claims.sub })`). The runtime appends context to the LLM conversation as text (`src/runtime/run.ts`), so client-supplied context would be a manipulation vector. Approval stays with the configured `ApprovalPort` (deny by default); no request carries approvals, allowlists or policies. | Client context as-is, or merged with server context. |
| D7 | **The authoring skill is exposed** — `skills/agentic-ddd` and the generated dev skills — as MCP resources mirrored by a read tool (`authoring_guide`), because client support for resources and prompts is unverified; a research step opens phase 2. Runtime skills stay out: they describe operation, not authoring. | Tools only, or resources only. |
| D8 | **A proposal is `proposal.md` plus a structured JSON delta** (entities, invariants with `id` and `text`, methods, events, use-cases and `uses`), validated by a zod schema. **The server renders the decorated skeleton** (`notImplemented()` bodies) deterministically. Clients never send TypeScript. | Text only: the client never sees the structure. Client-sent TypeScript: `compile` imports the project's modules (`src/compiler/load.ts`), so compiling client code is remote code execution. |
| D9 | **Server-side compilation only runs server-generated code**: identifiers validated against an allowlist regex; every client string (`text`, `description`, `instructions`) emitted as an escaped literal, never interpolated; compilation in an ephemeral worktree per request, with a timeout and no network. | Sandboxing arbitrary client code. |
| D10 | **The output of a proposal is a compiled bundle returned to the caller.** The server is stateless. The bundle is versioned and hashed, carries `baseRef` and the base lock hash, and has two layers: a **neutral layer** (IR delta, invariants with given/when/then acceptance examples, transitions, events, use-cases, acceptance criteria and one brief per item with no TypeScript paths or syntax) and an optional **`nestjs-ts` target** (decorated skeleton, packets with `specHash`, current briefs, updated dev skill, initial `todo` state). A short `BUNDLE.md` opens it: what it is, its base, the items in wave order and the exact commands. Briefs reuse ADR-0003's generator and token ceiling, so a low-cost model can act on the bundle alone. Publishing as branch + PR through a `ChangeSink` port is optional and needs `change:publish`. The new `agentic apply <bundle>` writes the TS target into `changes/NNNN-<slug>/`, refuses on a base mismatch and runs `compile`. | A server-side inbox (state, UI and approval flow). Committing straight to the main branch. Silent merge on base drift. |
| D11 | **Decorated TypeScript stays the only source of truth**, and the compiler stays the only producer of specs. A decorated repository may be a **spec repository** whose bodies remain `notImplemented()` forever, implemented elsewhere in PHP, Java, Python, Rust or any language. NestJS and the operator runtime are the reference target, not a requirement. | A language-neutral declaration format (YAML/JSON) as the source: rewrites the compiler. |
| D12 | **`done` is certified only for the `nestjs-ts` target** (`verify`, `specHash`, gates). Other languages get the specification and acceptance examples, uncertified. A neutral verification protocol (a test runner emits `invariant id → pass/fail` JSON, checked by `agentic verify --report`) is a separate issue. | Building that protocol now. |
| D13 | **Language**: framework-generated text (skill headings, the `AGENTS.md` block, briefs, `ROLE_CORES`, `BUNDLE.md`, the neutral layer, MCP tool descriptions, CLI and `verify` messages) is **English only, with no `locale` option**, as a breaking change in v0.6. Errors carry stable codes (`invalid_identifier`, `base_mismatch`, …). Business text (`text`, `description`, `instructions`, `proposal.md`) stays in the author's language and is never translated. `BUNDLE.md` and tool descriptions instruct agents to reply to the user in the user's language and never translate identifiers, invariant ids or business text. The MCP imposes no language on identifiers; teams that want one declare it in `.ai/rules`. New documents in this repository are written in English. | A `locale` option with `pt-BR` and `en`: doubles templates and snapshots. Requiring English identifiers: blocks non-technical clients describing their own business. |
| D14 | **Proof by pre-registered measurement**, in the style of cycle-22: a low-cost model (Haiku) receives **only the bundle** and must (a) answer comprehension questions (as in #18) and (b) implement the items until `verify` returns `done`. Baseline: cycle-21 A0 (Sonnet medium). One extra arm implements from the neutral layer in Python, against tests the pre-registration writes from the acceptance examples. Thresholds are fixed in the pre-registration, before any run. | Asserting comprehension and language neutrality without measuring them. |

## Consequences

- **Delivery as one epic in phases**, absorbing #69 (phase 1) and #11 (phase 4):
  0. Generated text, briefs, `ROLE_CORES` and the authoring skill in English (D13).
  1. Remote domain MCP with OAuth resource server and the current read tools (D2–D4).
  2. Authoring skill over MCP, preceded by client-support research (D7).
  3. Proposals, compiled bundle, `agentic apply` and the D14 measurement (D8–D12, D14).
  4. Runtime MCP with operators as tools (D5, D6).
- **Separate epics**: the unattended implementer that consumes published proposals (code written from external text is a different risk class); migrating the rest of the repository to English, with ADR-0001–0006, validation records, research and past CHANGELOG entries kept as history. A separate issue covers the neutral verification protocol (D12).
- **Measurement baselines break**: translating `ROLE_CORES` and briefs changes the `agent-briefs` snapshot and the text measured in cycle-21 and in the review benchmark; the D14 measurement doubles as the after-picture.
- **ADR-0005 D7/D8 no longer hold** as "read-only, no write tools, no repository access" for the remote server; the local stdio MCP of #68 is unchanged.
- **New attack surface**: public HTTP endpoints, OAuth, server-side compilation and, in phase 4, write actions through operators. Each phase's PR carries a full security review.
