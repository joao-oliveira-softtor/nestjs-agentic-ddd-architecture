# ADR-0004 — Camada de provider do Plano 7 (`LlmPort` real)

- **Status:** Proposto e **adiado** (nada decidido nem implementado)
- **Data:** 2026-10-13
- **Origem:** [issue #7](https://github.com/joao-oliveira-softtor/nestjs-agentic-ddd-architecture/issues/7) (Plano 7) e decisão do usuário de pausá-lo
- **Relacionados:** [ADR-0001](ADR-0001.md) D3, D4 e D16; [ADR-0003](ADR-0003.md); [plano da campanha de code review](../superpowers/plans/2026-10-12-code-review-fixes.md), Fase 7

Neste ADR, as referências a decisões de outros ADRs dizem `ADR-0001 D<n>` ou `ADR-0003 D<n>`.

## Contexto

O `OperatorRuntime` (`src/runtime`) fala com o modelo só pela porta `LlmPort`, e a única implementação é o `FakeLlm`. O Plano 7 existe para escrever o primeiro adapter real. A issue #7 exige escolher **um único provider ou SDK**, justificar a escolha com a documentação oficial, e declara fora de escopo o suporte simultâneo a vários providers, o streaming e um novo sistema de aprovação.

O `ADR-0001 D3` adiou o adapter real e descartou "Adapter Anthropic direto" e "Vercel AI SDK", **só para o v0** ("infra fica para depois"). O `ADR-0001 D4` fixa pacote único com fronteiras internas.

Em 2026-10-13 o usuário decidiu limitar o foco aos **agentes de desenvolvimento** (Claude Code, Codex, Cursor) e **não** implementar agora a camada de infraestrutura de operators. O Plano 7 fica em pausa. A pergunta que guia o trabalho atual é se modelos menores, como Haiku, entregam a demanda (épico [#26](https://github.com/joao-oliveira-softtor/nestjs-agentic-ddd-architecture/issues/26), `ADR-0003`).

## Decisão

1. **Nenhuma decisão de provider agora.** O Plano 7 não tem spec nem plano versionados; os de 2026-10-13 foram descartados e ficam no branch local `backup/plan7-spec` (commit `dc1b711`).
2. **O Mastra é o candidato registrado** para a camada de provider, a avaliar quando o Plano 7 voltar. Esta é a preferência do usuário, e não uma conclusão deste ADR.
3. O que for escolhido segue `ADR-0001 D3` (adiada, não revogada) e exige atualizar este ADR para "Aceito".

O `model` é uma string `provider/model` (por exemplo `anthropic/claude-sonnet-4-6`) resolvida por um model router, com chave por variável de ambiente por provider. Bun é listado como runtime suportado, sem versão mínima. ## Critérios para avaliar quando o Plano 7 voltar

Cobrem o que os documentos consultados não respondem:

- `AbortSignal` e timeout cooperativo repassados ao provider.
- Erro classificado com a `cause` preservada.
- `providerPayload` opaco, devolvido sem alteração no turno seguinte.
- `toolChoice` `auto`/`none` e resultados de tools agrupados numa só mensagem.
- Relato de uso (tokens) medido, sem estimativa.
- Peso como `peerDependency` opcional e comportamento no Bun 1.4.x.
- Custo de distribuição de um novo subcaminho (`ADR-0001 D4`): `exports`, `files`, `tsconfig.json`, `tsconfig.package.json`, `package-audit`, `package-transform`, `package-smoke`, testes de pacote e `docs/distribution.md`.

Da revisão de código do runtime (F8) da campanha de code review. Estavam na spec descartada (`docs/superpowers/specs/2026-10-13-plan7-llm-adapter-design.md` no commit `dc1b711`, branch `backup/plan7-spec`). Linhas conferidas em 2026-10-13.

| a | `src/runtime/ports.ts:9-11`; `src/runtime/run.ts:51-56`, `:96` | `complete(request)` não recebe sinal; ao estourar o timeout a chamada ao provider continua em voo | Sinal de cancelamento opcional no segundo parâmetro; o run aborta no timeout |
| b | `src/runtime/run.ts:214-218`; `src/runtime/types.ts` | Qualquer exceção do provider vira `provider_error`; o erro original se perde | Preservar a `cause` e classificar a falha em campo opcional, sem mudar `reason` |
| c | `src/runtime/run.ts:108-117`, `:211` | `max_tokens` e `refusal` já terminam na hora (`run.ts:98-100`). Só uma resposta `tool_calls` **sem nenhum bloco `tool_call`** chega à mensagem `tool` vazia (`:211`) e repete até `step_limit` | Terminar na hora com motivo explícito apenas nesse caso, sem alterar os términos existentes de `max_tokens` e `refusal` |
| d | `src/runtime/event-bus.ts:28-40` | Subscriber que lança interrompe a entrega e rejeita `publish` | Isolar o erro por subscriber e reportar por canal próprio |

## Consequências

- O Plano 7 e o Plano 8 (demonstração CLI com LLM real, issue #8) ficam bloqueados até o usuário retomá-los.
- Nenhuma dependência nova entra no `package.json`.
- Quando o Plano 7 voltar, a spec e o plano são reescritos sobre o código então vigente, partindo destes critérios e destes requisitos.
- Os requisitos (a) e (b) alteram o contrato do `LlmPort` e emendam a spec v0 (§9.1 e §9.5); isso é feito no PR de implementação.
