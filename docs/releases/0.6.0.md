# Release v0.6.0

The first release on the npm registry, as [`agentic-ddd`](https://www.npmjs.com/package/agentic-ddd). It makes the Domain MCP the entry point for remote agents (ADR-0007): served over HTTP behind OAuth with per-module access, able to serve a published lock, and able to turn a Delta into a compiled bundle that `agentic apply` and `publish_change` take to a pull request. It also adds the Elysia adapter (ADR-0008) and native Windows support, and switches every message and generated text to English with stable error codes. The [changelog](../../CHANGELOG.md) has every detail.

## Install

Requires Bun 1.4.2 or later, and the peers Nest 12, reflect-metadata and rxjs shared with the application.

```bash
npm install agentic-ddd @nestjs/common@^12 @nestjs/core@^12 reflect-metadata@^0.2.2 rxjs@^7.8.1 zod@^4
./node_modules/.bin/agentic-ddd compile
./node_modules/.bin/agentic-ddd compile --check
```

The GitHub release also carries the published tarball and its `SHA256SUMS`. [Compatibility and the public imports](../distribution.md).

## Upgrading from 0.5.0

- **Package name.** Imports change from `nestjs-agentic-ddd-architecture/<boundary>` to `agentic-ddd/<boundary>`, for example `defineConfig` from `agentic-ddd/compiler`. The binary is still `agentic-ddd`.
- **English output (#109, #110, #111).** Generated skills, the `AGENTS.md` block, CLI and verify messages, packets, briefs and the authoring skill are English only. Run `agentic-ddd compile` once: until then `compile --check` reports the old generated files. Business text (descriptions, invariant `text`, proposals) stays in the author's language.
- **Error codes (#111).** Every error carries a stable code (`config.key-unknown`, `verify.docs-outdated`, ...), listed in `ERROR_CODES`. Match on the code, not on the message.
- **Installed agent adapters (#110, #128).** Remove the `agentic-ddd-*` adapters from `.claude/agents`, `.codex/agents` and `.cursor/agents` and run `skills:install` again: the old text counts as a conflict.
- **`packet` (#159).** It never runs tests now, so its State line is always the static one. `verify --item` runs only the test files that cover the item; `verify <NNNN>` still runs the whole suite.

## What is new

- **Domain MCP over HTTP (#112, #113, #137, #139):** `agentic-ddd mcp --http` serves the read tools behind an OAuth 2.1 resource server (the authorization server stays external), with `domain:read:<module>` scopes and a Host/Origin allowlist. `jose` is an optional peer, needed only for `--http`.
- **Published lock (#114):** `agentic-ddd publish-lock` writes a digest-checked artifact the MCP server can serve instead of the working copy.
- **Authoring over MCP (#116):** `authoring_guide` and `skill://` resources serve the authoring skill, the dev skills and the team rules.
- **From Delta to pull request (#117 to #122, #144, #156):** `propose_change` validates a Delta and returns a compiled bundle (skeletons with the `nestjs-ts` target, plus a language-neutral layer with briefs), `agentic apply` applies it after hash and base checks, and `GitHubChangeSink` publishes it as a branch and pull request, refusing a bundle whose base moved.
- **Elysia adapter (ADR-0008):** `agentic-ddd/elysia` mounts the same decorated domain on Elysia, with typed use-case routes for Eden. `elysia` is an optional peer.
- **Native Windows (#128):** `compile`, `skills:install` and the package test work on Windows without WSL, and the CI runs the gate on `windows-latest`.
- **Fixes (#157, #158):** an opaque bearer token gets a 401 challenge instead of a 500, and an operator `timeoutMs` above the `setTimeout` maximum is refused at registration.

## Known limits

Open issues worth knowing before adopting this version: events published by a use-case without `await` can be dropped after it ends (#183); a second `agentic()` in a sibling Elysia sub-app is not rejected (#184); a use-case run outside an operator has no deadline (#186). The audit follow-ups are #160 to #176. The cycle-22 measurement (ADR-0006 D10) is still pre-registered and not run.
