# Release v0.7.0

A robustness release: 18 issues from the audit of 0.6.0 and from the reviews that followed. It changes how the runtime treats events, errors and deadlines, makes the compiler hold up on Windows checkouts and on failures in the middle of a run, tightens the Domain MCP's scopes, and trims the CI. There is no new surface beyond what those fixes need. The [changelog](../../CHANGELOG.md) has every detail.

## Install

Requires Bun 1.4.2 or later, and the peers Nest 12, reflect-metadata and rxjs shared with the application.

```bash
npm install agentic-ddd@0.7.0 @nestjs/common@^12 @nestjs/core@^12 reflect-metadata@^0.2.2 rxjs@^7.8.1 zod@^4
./node_modules/.bin/agentic-ddd compile --check
```

The GitHub release also carries the published tarball and its `SHA256SUMS`. [Compatibility and the public imports](../distribution.md).

## Upgrading from 0.6.0

Check these before you upgrade; each one changes behaviour that code or tests may rely on.

- **`UseCaseContext.signal` is required (#164).** Code that builds a context by hand must provide an `AbortSignal`. `createTestContext` provides one.
- **The default event bus keeps no events (#162).** A test that reads `bus.events` builds the bus with `new InMemoryEventBus({ record: true })`. Without it `events` stays empty, silently.
- **A throwing subscriber no longer fails the publication (#161).** Its error goes to `onError(error, event)`, or to `console.error`. A run no longer ends `failed` because a subscriber threw after the use-case saved.
- **New termination reasons (#160).** A failure of the `ApprovalPort` ends `failed` / `approval_error` and a failure of the event bus ends `failed` / `event_bus_error`. Both used to be `use_case_error`.
- **Event payloads are validated (#163).** An event whose payload does not match its `@AgentEvent` schema is refused like an undeclared event.
- **A publish is awaited by the runtime (#183).** `ctx.publish` reaches the bus in one call per batch, and a use-case that does not await it now waits for the bus before its execution ends. A bus failure fails the execution even when the use-case swallowed it or threw an error of its own.
- **`executeUseCase` rejects with the refusal (#160).** The error names the event, instead of the generic "published an undeclared event".
- **MCP: a token without `domain:read` is refused by the domain tools (#166).** A `skill:read`-only token used to get empty results.
- **`compile` fails on an unreadable `AGENTS.md` or `CLAUDE.md` (#169).** It used to treat the file as absent and overwrite it.

## What is new

- **`OperatorRunResult.error` (#160):** what was thrown, the refusal of an event, or the `ZodError` of an invalid output. It is the raw object: it can hold sensitive data and can be circular, so do not return or log the whole result as is.
- **`ctx.signal` (#164):** aborted when the run's deadline is reached. Aborting only notifies; a long use-case checks it before `save`.
- **A deadline outside an operator (#186):** `useCaseTimeoutMs` bounds a use-case run by an Elysia route (504 `runtime.use-case-timeout`) or by `executeUseCase` (as `options.timeoutMs`). The deadline bounds the wait, not the work: a 504 can come after `save` committed, so a route a client retries should be idempotent.
- **Elysia (#184):** a second `agentic()` that reaches an app through a sibling sub-app fails the mount.
- **Compiler on Windows checkouts (#167, #168):** a `proposal.md` with a UTF-8 BOM parses, archived proposals hash the same on LF and CRLF checkouts, and `compile --check` ignores a difference that is only line endings.
- **Compiler under failure (#169, #170):** the lock and `AGENTS.md` are written atomically, and `compile` no longer deletes the generated skills before it rewrites them.
- **`skills:example` (#173):** a failure removes the half-built destination and explains the Windows symlink error.
- **MCP HTTP (#165):** the server no longer redoes the same work on every request.
- **Trust model of `agentic apply` (#178):** ADR-0007 D15 and `BUNDLE.md` state that applying a bundle runs its code.
- **CI (#171, #172):** superseded pull-request runs are cancelled, jobs have time limits, and six unused devDependencies are gone.

## Known limits

- The second-mount check of the Elysia plugin does not see an `agentic()` inside the app's own `.group()` or `.guard()` when another one is already on the root.
- `useCaseTimeoutMs` is one value for the whole runtime; there is no per-use-case timeout.
- The IR describes an event payload after transforms and defaults, while the runtime delivers the payload as the use-case built it.
- On a case-insensitive filesystem, a stale generated skill directory that differs from a kept one only by letter case is removed after the new files were written into it; a second `compile` fixes it.
- A `.ai/rules/*.md` file with a BOM still fails, and `skills:install --check` still compares adapters byte for byte on a CRLF checkout.
- The Runtime MCP (#123, #124) and the cycle-22 measurement (ADR-0006 D10) are not in this release.
