# Release v0.4.0

Adiciona um tarball instalável em outra aplicação com exports públicos das seis fronteiras e a CLI `agentic-ddd`. A distribuição no GitHub inclui código-fonte, tarball auditado e evidências de validação. O nome `nestjs-agentic-ddd-architecture` permanece provisório; `private: true` e `prepublishOnly` continuam bloqueando publicação no registro npm.

## Instalação do tarball

Requer Bun 1.4.2, npm e os peers Nest 12, reflect-metadata e rxjs compartilhados com a aplicação. Baixe o asset `nestjs-agentic-ddd-architecture-0.4.0.tgz` e confira seu hash no `SHA256SUMS` da release.

```bash
gh release download v0.4.0 --repo joao-oliveira-softtor/nestjs-agentic-ddd-architecture --pattern '*.tgz' --dir /tmp/agentic-package-new
# Na aplicação consumidora:
npm install /tmp/agentic-package-new/nestjs-agentic-ddd-architecture-0.4.0.tgz @nestjs/common@^12 @nestjs/core@^12 reflect-metadata@^0.2.2 rxjs@^7.8.1 zod@^4
./node_modules/.bin/agentic-ddd compile
./node_modules/.bin/agentic-ddd compile --check
```

O config do consumidor usa `defineConfig` do export `nestjs-agentic-ddd-architecture/compiler`. Importe as fronteiras públicas `core`, `decorators`, `compiler`, `runtime`, `nestjs` e `testing`; a raiz exporta core. Não acrescente aliases do checkout ao tsconfig. [Compatibilidade e exemplo](../distribution.md), [fixture completa](../../test/fixtures/package-consumer).

## Build e reprodução

`bun run build` gera biblioteca ESM/CLI modular com declarações e maps. A aplicação demonstrativa mudou para `bun run build:app`; `start:prod` requer esse build. CommonJS não tem export require, e NodeNext/bundler validam declarações sem certificar o runtime completo em Node. Preserve os maps ao empacotar o consumidor: localização e hash fazem parte do contrato.

```bash
git clone https://github.com/joao-oliveira-softtor/nestjs-agentic-ddd-architecture.git
cd nestjs-agentic-ddd-architecture
git checkout v0.4.0
bun install --frozen-lockfile
bun run typecheck
bun run lint
bun test
bun run build
bun run test:package
bun run agentic compile --check
bun run skills:install --check
```

A suíte do runner requer Linux/bubblewrap. `test:package` faz npm pack, audita o tarball real, instala com npm em consumidor temporário, valida declarações NodeNext/bundler com skipLibCheck false e imports privados bloqueados; executa a CLI, geração/check de skills, operator via DI e bundle. Fonte/bundle preservam o mesmo resultado, IR e `src/shop/domain.ts:12`. O smoke limpa os artefatos temporários.

Os resultados finais, commit/árvore, hashes e CI constam no asset `validation-v0.4.0.json`. O tarball publicado é auditado novamente e incluído em `SHA256SUMS`; o nome do pacote e o bloqueio de publicação são mantidos também dentro dele.
