# Release v0.5.0

Adiciona o modelo tático do domínio: value objects, relações entre agregados (`contains` e `references`), ports, adapters de infraestrutura e gates T1 a T3 no `verify --item`. Inclui também as regras do time, o servidor MCP local e o tutorial `matriculas`, com o braço de controle do ciclo 22 pré-registrado. Sem decorators táticos (VO, `contains`/`references`, port, adapter), a árvore gerada e a IR não mudam por causa da v0.5 tática; a #63 e o snapshot do MCP (#68) são mudanças à parte desta versão. O nome `nestjs-agentic-ddd-architecture` permanece provisório; `private: true` e `prepublishOnly` continuam bloqueando publicação no registro npm.

## Instalação do tarball

Requer Bun 1.4.2, npm e os peers Nest 12, reflect-metadata e rxjs compartilhados com a aplicação. O asset `nestjs-agentic-ddd-architecture-0.5.0.tgz` e o `SHA256SUMS` ficam disponíveis quando a release v0.5.0 for publicada; confira o hash antes de instalar.

```bash
gh release download v0.5.0 --repo joao-oliveira-softtor/nestjs-agentic-ddd-architecture --pattern '*.tgz' --dir /tmp/agentic-package-new
# Na aplicação consumidora:
npm install /tmp/agentic-package-new/nestjs-agentic-ddd-architecture-0.5.0.tgz @nestjs/common@^12 @nestjs/core@^12 reflect-metadata@^0.2.2 rxjs@^7.8.1 zod@^4
./node_modules/.bin/agentic-ddd compile
./node_modules/.bin/agentic-ddd compile --check
```

O config do consumidor continua usando `defineConfig` do export `nestjs-agentic-ddd-architecture/compiler`, e as fronteiras públicas são as mesmas da v0.4.0, mais `mcp` para o servidor local. Não acrescente aliases do checkout ao tsconfig. [Compatibilidade e exemplo](../distribution.md).

## Elementos táticos

Os decorators novos são opcionais. Sem eles, a v0.5 tática não muda a saída do `compile`.

- `@AgentValueObject({ description })` declara um value object como item `valueobject:<Nome>`, com as invariantes cobertas por `covers`.
- `@AgentEntity({ contains, references })` declara a composição e a referência entre agregados no dono. O contido entra antes do dono no grafo; a referência é só por id e não cria aresta. A raiz é derivada: a entidade que nenhum `contains` cita.
- `@Invariant` também vale em `@AgentUseCase`, para regras que atravessam agregados, com id `invariant:<usecase>/<id>`.
- `@AgentPort({ description, root, methods })` declara a interface de um repositório em classe abstrata. Mudar o port exige proposta.
- `@AgentAdapter({ description, implements })` declara a implementação de um port na camada `infrastructure`, com uma obrigação por método do port. Na v0.5 há um adapter por port.

O gate de escopo de classe confere, para value objects e adapters, que o executor altera só corpos e campos `#privados`, sem tocar em decorators, `extends`/`implements` ou na assinatura pública.

Os gates T1 a T3 aparecem no `verify --item` de itens `entity:` e `valueobject:` quando o projeto tem elemento tático. Eles leem a árvore sintática do código, não o TypeChecker, e não rodam em `status` nem em `verify NNNN`. Têm falsos negativos conhecidos, listados em [authoring.md](../../skills/agentic-ddd/references/authoring.md#gate-t): alias de tipo, tipo sem anotação e import renomeado não são detectados.

## Demonstração reproduzível

O tutorial `matriculas` é o caminho para reproduzir o modelo tático do início ao fim:

```bash
bun run skills:example --root ./scratch/agentic-matriculas --tutorial matriculas
```

O destino precisa não existir. O tutorial tem sete itens: as entidades `Aluno`, `Turma` e `Matricula`, os value objects `AlunoId` e `TurmaId`, o use-case `matricular_aluno` com as invariantes `aluno-ativo` e `turma-com-vaga` e os ports `MatriculaRepository`, `AlunoRepository` e `TurmaRepository`, e o adapter `InMemoryMatriculaRepository`. "Turma com vaga" é conferida pelo use-case, contando as matrículas da turma; a corrida entre duas matrículas simultâneas fica documentada na proposta, porque não é invariante transacional. Quatro armadilhas têm testes privados próprios: guardar o `Aluno` inteiro, regra que atravessa agregados, value object com invariante e consulta própria no repositório.

O tutorial `tasks` continua disponível sem `--tutorial`; a árvore gerada não muda com a opção nova (um teste confere o hash).

## Controle do ciclo 22

O pré-registro de `evals/campaigns/cycle-22-control/` compara dois braços no tutorial `matriculas`: C0, com packet mínimo e sem skill, regras ou gates no laço, e F, com o framework completo. Os dois usam a v0.5.0, o mesmo esqueleto declarado, o mesmo modelo e comparação pareada por item. O pré-registro declara as métricas (aceite pelo oráculo privado, violações T1/T2 e defeitos por armadilha) e aceita "inconclusivo" como resultado previsto.

Nenhuma inferência real foi executada para esta release. O ensaio usou só o adapter `scripted`. A execução real depende de orçamento autorizado à parte e deve atualizar o `sourceRef` dos manifestos antes de rodar.

## Build e reprodução

`bun run build` gera biblioteca ESM/CLI modular com declarações e maps. A aplicação demonstrativa usa `bun run build:app` antes de `start:prod`. Preserve os maps ao empacotar o consumidor: localização e hash fazem parte do contrato.

```bash
git clone https://github.com/joao-oliveira-softtor/nestjs-agentic-ddd-architecture.git
cd nestjs-agentic-ddd-architecture
git checkout v0.5.0
bun install --frozen-lockfile
bun run typecheck
bun run lint
bun test --path-ignore-patterns='test/evals-*'
bun run agentic verify 0001
bun run build
bun run test:package
bun run agentic compile --check
bun run skills:install --check
```

A suíte do runner requer Linux/bubblewrap. `test:package` faz npm pack, audita o tarball real, instala com npm em consumidor temporário e valida declarações NodeNext/bundler com skipLibCheck false. Os resultados finais, commit/árvore, hashes e CI vão para o asset `validation-v0.5.0.json`, que estará disponível quando a release for publicada.

## Continuidade

Sem decorators táticos, a árvore gerada e a IR não mudam por causa da v0.5 tática; a #63 e o snapshot do MCP (#68) são mudanças à parte desta versão. O `evals:aggregate` e os relatórios históricos seguem preservados. O épico #26 está encerrado. A issue #69 (servidor MCP remoto) segue aberta, e o épico #70 continua aberto por causa dela. Ficam para a v0.6 ou depois: gates pelo TypeChecker, checagem de agregado mutado por use-case, regras de corpo, value object imutável, finders novos no MCP e adapters que não sejam de repositório. O provider real de LlmPort e a CLI de operação permanecem nos Planos 7–8. [Changelog](../../CHANGELOG.md) e [roadmap](../ROADMAP.md).
