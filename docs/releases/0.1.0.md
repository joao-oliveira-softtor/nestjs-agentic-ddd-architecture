# Release v0.1.0

A primeira release publica a base descrita nos quatro planos do marco interno **v0**. O número público é **v0.1.0**; a próxima etapa proposta é **v0.2.0**, com validação usando agentes e LLMs reais. O histórico da spec mantém sua nomenclatura original; as versões públicas e prioridades atuais ficam no [roadmap](../ROADMAP.md).

## Demonstração reproduzível

Requer Bun 1.4.2 e Git.

```bash
git clone https://github.com/joao-oliveira-softtor/nestjs-agentic-ddd-architecture.git
cd nestjs-agentic-ddd-architecture
git checkout v0.1.0
bun install --frozen-lockfile
bun run agentic compile --check
bun test examples/orders/test/operator.test.ts
```

Resultado esperado: três E2E aprovados. O primeiro compila uma skill em saída temporária, carrega-a com hash validado na composição Nest e usa FakeLlm para criar/confirmar o pedido. Os outros demonstram cancelamento com aprovação negada e concedida, verificando ausência de execute/eventos na negação.

Para consultar a coordenação:

```bash
bun run agentic status --static
bun run agentic next --json
bun run agentic packet operator:order-operator
```

`status --static` não certifica `done`. `next` e `packet` executam os testes e pode levar alguns minutos; com a suíte passando e toda cobertura presente, `next` devolve uma lista de ondas vazia. Consultas sem testes continuam válidas sem inventar evidência de conclusão.

## Verificação da release

```bash
bun run typecheck
bun run lint
bun test
bun run build
bun run agentic compile --check
bun run agentic verify 0001
bun run agentic verify 0002
```

Validação executada: **354 testes, zero falhas, 14 snapshots preservados**. `bun install --frozen-lockfile`, typecheck, lint, build e compile --check aprovados; verify 0001 = done; verify 0002 = needs-human, somente G6 do exemplo.

O G6 é um critério manual do domínio demonstrativo: revisar o texto “Informe o motivo do cancelamento.” Nenhuma aprovação humana é presumida. O exemplo preserva a saída `needs-human` para demonstrar esse contrato; isso não impede o lançamento do framework.

## Uso e distribuição

As skills ficam em `.agents/skills` e `.agentic/runtime`, com os arquivos gerados versionados. O quickstart Nest e os contratos de runtime estão no [README](../../README.md).

O build mantém `BunAdapter` e emite `dist/main.js` e `dist/main.js.map`; o `.map` é necessário ao runtime empacotado. A composição padrão usa FakeLlm de roteiro vazio; a demonstração acima fornece roteiros por TestingModule, com chamadas diretas ao OperatorRuntime. As próximas issues tratam provider real, canal CLI e distribuição npm.
