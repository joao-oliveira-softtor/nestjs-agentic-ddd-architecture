# AGENTS.md

Este repositório é o framework `@agentic-ddd` (em `src/`) e o app de exemplo `examples/orders`.

## Desenvolvimento do framework

- Runtime, testes e build: Bun (`bun test`, `bun run typecheck`, `bun run lint`, `bun run build`).
- Gate do CI (`.github/workflows/ci.yml`): `typecheck`, `lint`, `bun test --path-ignore-patterns='test/evals-*'`, `agentic verify 0001` (`done`), `build`, `test:package`, `compile --check`, `skills:install --check`; job à parte `bun test test/evals-` (~27 min, não editar o worktree enquanto roda); `bun test` puro inclui esse job, então a linha de base local usa o comando do `ci`.
- CI local em Linux: `bun run ci:docker` roda o gate do `ci` (ou `-- <comando>`, como `crapper`, `dryer` e `mutator`) num container com o Bun do CI, sobre um snapshot da árvore de trabalho; não cobre o job `evals`. Veja o README.
- Design: `docs/superpowers/specs/2026-10-06-agentic-ddd-v0-design.md`; decisões: `docs/adr/ADR-0001.md`; planos: `docs/superpowers/plans/`.
- `examples/**` importa o framework só via `@agentic-ddd/*`; `src/core` só importa `zod`.
- Testes com `bun:test`; snapshots em `__snapshots__/` são revisados como código.
- Teste novo em `test/` fora de `evals-*` entra em `verify.test` do `agentic.config.ts` (o `evals-verification-scope` confere); teste que roda `verify --item` aninhado vai como `test/evals-*`.
- A sessão principal deve planejar com o ecc:plan e coordenar o trabalho separando em tasks identificando dependências entre as tasks e direcionando-as para subagents
- Modelo de cada subagent pelo trabalho, sempre explícito no dispatch (um fork herda o modelo da sessão): haiku para tarefa mecânica com brief completo (resolver conflito de `CHANGELOG.md`); sonnet como padrão de implementação, correção, revisão de escopo claro e medição ub-mode (julgar mutante equivalente pede critério); opus para arquitetura, segurança, revisão final e causa raiz difícil. Escreva o brief para que o modelo mais barato que dá conta da tarefa a conclua sem perguntar. Isso vale para desenvolver este repo; o padrão do framework para os adaptadores continua `model: inherit` (ADR-0003).

## Skill autoral e agentes

- A skill do framework tem fonte autoral em `skills/agentic-ddd/`; ela orienta autoria e papéis gerente/executor. As skills `<módulo>-dev` e de runtime são geradas e descrevem o domínio.
- Instale com `bun run skills:install` (projeto/todos), `--scope user` (global explícito), `--target cursor|codex|claude|all`, `--root <raiz>`, `--check` e `--mcp` (opt-in: grava a config do servidor MCP local de cada agente). Links dependem da permanência deste checkout.
- `.agents/skills/agentic-ddd` e `.claude/skills/agentic-ddd` são links autorais instalados, preservados por compile. Adaptadores em `.cursor/agents`, `.codex/agents` e `.claude/agents` são instalados pelo script; altere a fonte ou o instalador, respeitando conflitos ao reinstalar.
- Tutorial isolado: `bun run skills:example --root <destino-inexistente>`; percurso em `skills/agentic-ddd/references/tutorial.md`. Não evolua orders para validar essa skill.
- `references/executor-domain.md` e `references/reviewer.md` viram `ROLE_CORES` nos briefs de todo projeto: editar muda o brief (e o snapshot de `agent-briefs`); linhas são presas por `classScopeCore` e pelo `review-benchmark`.

### Conventions

- Entities, methods, events, use-cases and operators are declared with `@AgentEntity`, `@AgentMethod`, `@AgentEvent`, `@AgentUseCase` and `@Operator` from `@agentic-ddd/decorators`; each business rule is an `@Invariant({ id, text })` with a stable ID.
- Where to create: `<module path>/domain` (entities, events, ports), `<module path>/application` (use-cases, always with `uses`), `<module path>/operators` (operators). The module's dev skill has the exact paths.
- Every public entity method has `@AgentMethod`; helper methods use `#private`.
- A declared body that is not implemented yet uses `notImplemented()` from `@agentic-ddd/core`.
- Coordination: check `bun run agentic status` or `next` (waves); run each item from `bun run agentic packet <item>` and validate it with `bun run agentic verify --item <item> --spec-hash <hash>`. `status --static` reads test declarations without running them and never certifies `done`.
- The skeleton signal only recognizes the literal `notImplemented()` call; an empty body counts as implemented. State is computed on demand and is not written into generated files.
- Tests declare what they cover with `covers([...ids], title)` from `@agentic-ddd/testing`.
- Business rule change: first write the proposal in `changes/NNNN-<slug>/proposal.md` (delta, acceptance criteria and a `## Motivo` section), implement it and run `bun run agentic compile`; for a change already made in the code, `bun run agentic compile --draft-change <slug>` generates the draft.
- A task is only complete when `bun run agentic verify <NNNN>` returns `done` or `needs-human`.
- Generated (do not edit): `.agents/skills`, `.agentic/runtime`, the skill mirrors and this block. Change the decorated code and run `bun run agentic compile`; CI runs `bun run agentic compile --check`.
